# 项目文档整理与追溯

这是共享能力，不是新增角色、平台或审批阶段。按[共用工作方法](../../../workflow/role-work-method.md)读取当前授权目标与现有入口；相关交接才读[Agent协议](../../../workflow/agent-protocol.md)。唯一方法来源是[文档标准](../../../standards/documentation/README.md)，只读当前任务有关段落。

先确认项目已有唯一中心、维护责任、实际检查/生成命令与CI触发；缺中心时在当前获授权接入/交付中安排最小建立，小任务可复用README，不因采用Skill宣称已自动生成。按[建立与接入要求](../../../standards/documentation/README.md#文档中心的建立与接入)落实。先确认读者要回答的问题、维护范围和既有权威来源。默认 **Lite**，在原README/任务内更新；阶段相关功能组用 **Standard**，首次整体建立或明确全项目复核才用 **Full**。深度不扩大权限、免除原Gate或要求生成全部未来规格。已有准确来源优先复用，无影响可说明理由后结束。

1. 按用途组织概览、需求、设计、Feature/追溯、质量、适用运维、当前决定和历史；组前一句话说明能回答什么。短链接在前，路径/版本/审计在后；逻辑分组不要求新物理目录。
2. 从原Catalog列出正式Feature，保留名称、阶段、稳定ID；新增/未来功能也可定位，缺资料如实显示。沿已有RTM补当前必要关系，正反向可查；不复制正文、步骤、结果或再算一套AC验收。
3. 每次有文档影响的交付主动执行[维护闭环](../../../standards/documentation/README.md#每次交付只维护受影响内容)：先检查已提交页/版本，再更新原来源与引用、按项目命令生成并交付、核验中心；历史批准固定原版本。核对项目CI覆盖实际输入的PR/主分支变更且先检查后构建；没有生成物只核链接/语义，无影响说明依据，不造构建或全库报告。
4. 外部状态使用真实读取或带时间快照，分开来源修订、观察时间和生成时间。局部刷新只更新对应条目；访问失败保留原时间与限制，不伪装实时或全库同步。
5. 当前Review Center先给问题、推荐、影响、版本、独立结论与未测项；核对旧待审是否已经处理或替代。没有待决事项就明确空状态，不新增报告或批准。

保留需求/设计、工作进度、测试设计/自动化/执行、完整AC与Owner验收的不同事实。参考项目只读材料不带入正式规范、默认上下文或配置；采用通用概念和合成示例，不复制实际项目的目录、ID、生成器或技术栈。

交付给出可打开的文档中心入口、改了哪些来源/关系、实际检查/生成结果及未同步项；未配置或检查失败不能报告已同步。给Owner看结论和待决事项，审计附后。机械链接检查、真实文件阅读、DOM、浏览器与真人可用性分别报告；不据文件存在宣称理解率或效率改善。权限/版本冲突只停止受影响动作，其他有界工作继续。
