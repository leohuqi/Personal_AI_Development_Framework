# 测试架构与质量策略约定

这是SA系统方案的内容约定，不新增机器Schema、全项目必填字段或独立审批。已有批准策略引用准确版本，仅在新系统或测试技术架构变化时补增量。可用[模板](../templates/testing-architecture.md)同文维护。

| 要讲清的事 | 足以指导项目实施的内容 |
| --- | --- |
| 工具选择 | 语言/运行时、测试框架与版本、现有能力、较简单替代和维护成本 |
| 类型与层级 | Functional/Non-functional与Unit/Component/API/Integration/E2E分别证明什么 |
| 边界与数据 | mock、fixture、必要真实依赖、隔离/清理，合成/脱敏数据和隐私 |
| 本地与CI | 可复现命令、实际环境、适用CI、失败传播及诊断保留 |
| Coverage | line/branch工具、包含/排除/零命中分母、风险要求；AC覆盖独立 |
| 报告与TDD | 准确版本/原件/阅读入口，TDD适用范围及代表性验证要求 |

以上合计覆盖框架选型、范围、层级边界、mock/真实依赖、数据隐私、本地命令、CI、coverage、报告和TDD十项关注点，不要求十份文档。项目自主选择工具；PADF不提供统一执行器或要求安装固定工具。命令是项目能力说明，不是跨项目执行授权。

交接固定策略/源版本、实际批准来源（如适用）及未决项，PROPOSED不能写成获批生产方案。方法效果按[共享标准](../standards/engineering/README.md#怎样判断方法有效)评估，策略存在本身不算已有效应用。
