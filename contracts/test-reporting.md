# 工程测试报告约定

统一含义，复用项目现有格式。JUnit XML、pytest/Allure/Playwright HTML、coverage原生报告或等价资料均可，不要求新建PADF适配器、机器Schema或部署服务。

| 状态 | 含义 |
| --- | --- |
| PASS | 实际断言通过，有相应版本证据 |
| FAIL | 实际断言/执行失败，保留差异与日志 |
| SKIPPED | runner明确跳过，不计已执行/通过 |
| BLOCKED | 必要环境、输入或依赖缺失，目标行为尚未得到验证 |
| NOT_RUN | 未运行或缺本轮执行证据，写明范围/原因 |

项目已有状态名可明确映射，不强制重命名机器枚举；不能把环境启动失败说成产品缺陷，也不能以报告上传/生成成功掩盖失败。

一页摘要回答：当前范围/版本是什么、哪些结果可用、还有哪些缺口、影响哪个决定、原件在哪里。按实际适用性引用：

- Run/执行者、准确实现与测试定义/需求版本、环境、工具版本、命令/退出码及时间；CI的PR head与checkout/merge版本分开。
- 唯一测试结果的五状态；line与branch各自工具、包含/排除和分母（含应纳入的零命中源码）；当前AC覆盖使用独立分母，不平均不相容口径。
- Feature/AC/TC/测试函数/Run的关联，完整与局部验证，候选及未测范围；测试已设计/自动化/执行/通过不等同AC充分或Owner验收。
- 原TC、测试源码、逐项结果/失败详情、日志、coverage与CI链接；不能只交一段字典或要求Owner逐行阅读完整RTM。
- 已知缺陷、阻塞/未测、剩余风险和必要Owner决定。历史报告注明其时点，实时状态另核对；PR正文中的旧状态不能覆盖平台实际合并事实。

摘要不复制完整证据，也不替代它。采用已有报告时只补缺口映射。框架方法评估可只读这些记录；读取项目命令或历史PASS不是执行项目测试的授权，也不是评估者亲自重跑的证明。见[工程标准](../standards/engineering/README.md)。
