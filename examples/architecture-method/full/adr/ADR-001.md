# ADR-001：用隔离解析与受控发布保护权威记录

SYN-FULL-B1；状态PROPOSED；批准引用null；本例不是实际产品决定。上下文：不可信文件处理可能超时/崩溃，数据/权限不能由解析进程自行决定。

建议保留一个模块化API拥有Record/Policy/Task发布，单独Parser只能领取精确输入和提交候选。简单替代是API请求内同步解析，部署更少但资源隔离/失败影响更大；全微服务替代增加分布式事务与运维，不符合当前小团队约束。选择隔离Parser是练习建议，尚未获批。

后果：Web上传完成与解析完成分开；引入任务lease/epoch、完整结果校验和失败恢复；Parser停机只积压，API仍提供获准原件读取。实际安全/性能依赖隔离、权限和存储能力，不能由图证明。

未批/未知：D1受管存储的条件创建/完整性、持久性与准确版本；D2独立备份介质/密钥/保留期限及RPO/RTO；D3身份提供方与会话撤销策略；实施级Schema/限额/租约值。SA负责验证建议、Owner决定重大取舍。批准与编码另行核验，未定前阻断依赖实施。条件变化通过新ADR替代，保留本编号及状态。
