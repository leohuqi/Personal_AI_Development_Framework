# PQA V0.3 specialist-design illustration — not an executed change

PQA is a *consumer* of PADF. This example does not modify PQA, approve UX or API changes, start Codex, or touch PQA Draft PR #7.

Example task: a new Stock Detail interaction may require Architect to trace stock/strategy APIs and produce a sequence diagram; UI Designer reads PQA's actual UI style/components (propose [UI Profile](../../contracts/project-ui-profile.md) if none is approved), creates a high-fidelity page design and potentially a working interactive prototype when the Owner determines it materially improves acceptance.

Master starts with actual PQA AGENTS.md, approved Feature Spec, immutable original Feature ID and real Linear task. Master marks impacted technical/UI stages and dependencies, chooses ordering, requests specialist artifacts and checks them against [Design Gate](../../contracts/design-gate.md). For L/XL or high-risk S/M the Independent Reviewer inspects exactly versioned design sources before Master can record DESIGN_READY. The Owner must separately authorize Coder implementation.

Never treat a K-line static concept image as proof of an interactive chart, a generated ER diagram as actual PostgreSQL DDL or an uninstalled diagram-design reference as successful execution. Use real PQA docs and SHA/issue links; don't copy PADF test identifiers into production tasks.
