## Boundaries and responsibilities
Conform exactly to Xcode 26.0 / Swift 6.2 / iOS 26 SDK / minimum iOS 17, native SwiftUI, Core Data LedgerModel v1, one offline process. Application ports coordinate adapters; adapters do not call one another. No network API: REST/OpenAPI/server DDL are N/A because no server or external HTTP contract exists. Core Data logical model and typed local APIs define the applicable API/DB contract. No new stack or material SYSTEM policy proposed.

ExpenseRecord covers manual entry, immutable import evidence, preview/review/atomic commit, local suggestions plus explicit override, duplicate decisions, refunds, location evidence and recovery seams. Full backup implementation, real provider compatibility, application build, UX styling, coding permission and release are outside this delivery.

## Invariants
I01 Money = ISO currency + signed Int64 minor units. Spend records carry positive amount; refund records carry negative amount, never Int64.min; zero invalid. Parse decimal strings exactly with checked multiply/add and currency exponent registry v1 (CNY/USD=2, JPY=0); no Float/Double. Unsupported currencies/excess decimals reject; no FX or cross-currency totals.
I02 Import evidence is immutable and separate from editable ledger values. Entry merchant/category/date/location corrections never rewrite source observations or source identity. Reimport cannot silently replace any existing value or explicit category choice.
I03 A commit is one durable persistent-store save for all selected entries, observations, identity reservations, refund links, overrides, batch and command receipts plus ledgerRevision increment. No intermediate child-context save counts as durable. Any validation/save failure rolls back all changes.
I04 Strong provider identity is unique per provider plus explicit local account namespace. Missing IDs are candidates only; identical economic fields may be different purchases. File identity alone never deduplicates overlapping exports.
I05 Refund records preserve independent identity, sign and evidence. Unresolved refunds remain visible separately and excluded from settled net. Links are same currency, negative refund to positive spend; sum of linked refund magnitudes cannot exceed spend. Original is never deleted or reduced.
I06 Current GPS is an optional present observation, never historical purchase location. Import does not request GPS. Denial/unavailability never prevents entry/import.
I07 Cancellation before transaction discards transient staging. Once atomic save begins, commit wins or fails; cancellation cannot claim rollback after durable save. Retry returns stored receipt after a successful commit.
I08 Logs contain only stable codes, counts/durations, ephemeral random correlation IDs; no amounts/merchant/coordinates/file names/raw IDs or hashes/keys. Store/provenance remain sensitive protected data, not anonymous analytics.

## Ownership and calculations
Category is a snapshot of suggestion (rule version, reason enum, confidence enum) unless an explicit user override exists. Override outranks user merchant mapping, which outranks bundled rules; ties use longest normalized literal match then rule ID ascending. No remote AI. Reclassification is an explicit reviewed command on selected entry IDs, never automatic mutation. Unknown/retired category cannot be selected for a new save; historical category remains readable after retirement.
Manual entries get UUID identity and no provider SourceIdentity. Imported entries get UUID plus zero/one strong identity; observations may also attach to an already known entry after review. A duplicate decision records keepSeparate, linkExisting, or skip with candidate IDs and observed revision. keepSeparate is allowed only for no-ID rows. Known conflicting provider ID cannot become a second entry; user may skip it and separately create a manual correction. Source original never mutates.
Settled net per currency = sum positive spend + sum negative refunds having valid RefundLink. Unresolved/refund-conflict subtotal is separate. All sums checked Int64; overflow returns INVALID_AMOUNT and no misleading total. No totals spanning currencies. Negative net for a particular spend is forbidden by link invariant.

## Timestamp, merchant and source rules
Normalize text NFC, trim Unicode outer whitespace, preserve case in display; merchant comparison uses locale-independent case fold and collapse internal whitespace. Do not strip punctuation/digits or resolve merchant aliases implicitly. Keep immutable normalized source merchant plus editable display merchant. HMAC fingerprint uses normalized comparison merchant.
occurredAtUTC is an exact second timestamp plus original offset seconds and precision enum. Synthetic profiles require RFC3339 explicit offset and second precision; reject missing zone, leap seconds, invalid calendar dates or ambiguous local time. Manual form supplies explicit IANA zone and fold choice for DST ambiguity, persists selected offset and UTC; nonexistent wall time rejects. Zone identifier is optional for fixed-offset imports. Local display changes never rewrite source time. A provider profile with another precision/timezone must define new normalization version and review, never assume device zone.
Account namespace is user-selected random UUID per local provider account, no login/account number; preview explicitly confirms it. Provider ID is exact NFC string with outer whitespace trimmed only, case-sensitive, max 256 UTF-8 bytes. Wrong namespace is user risk surfaced at review; never infer from names. Profile provider marker and namespace/provider pairing must match.

## Exact identity, overlap and conflict algorithm
All identity encodings use versioned domain-separated length-prefixed UTF-8 components (4-byte big-endian length), not delimiter joins. HMAC-SHA256 with random per-ledger 256-bit identityKey protects low-entropy IDs/fingerprints; key lives in protected private key material, never logs. Key exported only inside authenticated encrypted archive; restores preserve it. Key loss means recovery mode, not silently generating new keys for old data. This is an internal persistence detail under SYSTEM CryptoKit, not a new security boundary.
strongKey = HMAC(identityKey, [strong-v1, provider, namespaceUUID, providerID]).
economicDigest = HMAC(identityKey, [economic-v1, provider, namespace, kind, minorUnits decimal, ISO currency, UTC seconds, offset seconds, precision, normalizedMerchant, originalStrongKey-or-empty]). Status normalization participates; only settled records eligible. Category/location/suggestions/user edits/filename/row index do not participate.
fingerprint = HMAC(identityKey, [candidate-v1, provider, namespace, kind, minorUnits, currency, UTC seconds, precision, normalizedMerchant]); offset omitted here because equivalent instants can use different offsets. It is indexed NON-unique.
1. Stream bounded file to protected random staging name; SHA256 bytes; look up global fileDigest receipt. If already committed, same namespace/profile returns existing receipt; differing namespace/profile returns SOURCE_CONFLICT. Never apply new override decisions during replay.
2. Detect exactly one synthetic profile; parse/validate every row; failed rows are listed by ordinal+code. No commit until invalid rows explicitly excluded and all remaining review decisions complete. Preview is immutable candidate snapshot at storeEpoch/ledgerRevision and reviewRevision.
3. For each strong ID, search current store AND earlier rows in same batch. Same key+economicDigest -> exact duplicate proposal, preselected skip but visible until explicit confirmation. Same key+different digest -> SOURCE_CONFLICT (including changed amount/currency/status/refund reference); blocked row must be excluded. Do not silently replace evidence or merge statuses. Two identical strong rows may collapse to one identity/entry with two observation ordinals on explicit confirmation.
4. Without ID, search fingerprint across store and batch. Zero match proposes new entry; one/multiple matches require explicit linkExisting, keepSeparate or skip. Even within the same file no automatic collapse. keepSeparate creates UUID entry/source observation, no unique fingerprint constraint. linkExisting requires matching kind/currency/amount/instant/merchant source digest and explicit candidate selection; user corrections on existing entry remain intact. Ambiguous rows cannot be committed undecided.
5. Overlap example: export A IDs X,Y; B IDs Y,Z => Y proposed duplicate, Z new regardless file hash. Same no-ID rows in A/B => candidate review; multiple identical purchases remain separately representable. If canonical merchant was edited, match uses original immutable observations rather than edits.
6. Inside writer transaction, recheck epoch/revision, all identities, selected candidates, category validity and refund caps. Any stale observation returns STALE_REVIEW with no writes, forcing refreshed preview and explicit review. No automatic rebase of financial decisions.

## Refund algorithm and edge cases
A refund is one negative Entry associated with at most one positive original. Partial refund -300 of +1000 and another -200 leave +500 settled. Original ID references use strongKey with same provider/namespace; refund own strongKey is distinct. Self-reference, refund-to-refund, cross-currency, nonpositive original or over-cap are REFUND_UNLINKED/SOURCE_CONFLICT review blockers for linking, not data loss. Preview may choose retainUnresolved for missing/ambiguous original; commit negative entry with resolution=unresolved, no link. Explicit link command with expected revisions may later link all amount or leave all unresolved; splitting a single refund among multiple originals is unsupported and surfaced, never guessed. Multiple refunds have different IDs or reviewed separate no-ID entries.
When refund precedes original, retain unresolved and keyed originalStrongKeyHint. Arrival of original offers candidates but does not silently link; explicit review links it. Sort proposed refund links by original UUID then refund UUID only for deterministic checks; evaluate aggregate proposed+existing magnitudes together with checked arithmetic, not arrival order. If total exceeds cap, entire chosen link plan fails; user can leave selected refunds unresolved or skip rows, preserving all evidence. If several originals match a no-ID hint, explicit selection required. A full refund plus later partial exceeds cap and cannot settle automatically. Duplicate refund retries must never count twice. Non-settled/cancelled provider rows are excluded with code, not rewritten as refunds.

## Location and privacy
LocationEvidence is append-only, separated from Entry.occurredAt. source_provided_historical stores bounded text, no inferred coordinates/geocoding; user_entered_historical stores explicit text/coordinates if entered with provenance. device_current requires a foreground purpose token from explicit user action, collectedAtUTC, accuracy meters and authorization snapshot. Max wait 10 s, accept age <=60 s, horizontal accuracy >=0 and <=1000 m; reduced accuracy remains optional with UI warning and explicit accept, otherwise retain prior evidence. Denied/restricted/timeout/unavailable => nonfatal LOCATION_UNAVAILABLE or PERMISSION_DENIED, entry save remains available. A source history label and attached current observation coexist. Replacing display choice changes selectedLocationEvidenceID only; original source stays immutable. Consent token is bound to one entry/draft, expires 60 s, cannot attach to all batch rows. No background permission, no automatic retry/GPS on app reopen/import.

## Transaction, concurrency and restore
LedgerPersistence owns actor LedgerStore; its dedicated private NSManagedObjectContext runs perform closures. No managed objects cross actor boundaries; return Sendable value DTOs/UUIDs. MainActor owns presentation state. Parser/rules run non-main, cancellation every <=100 rows and before entering commit. One writer serializes manual/import/override/refund commands; error merge policy, no property-trump. No NSBatchInsert/NSBatchDelete bypassing constraints. Writer checks all uniqueness/domain rules; Core Data constraints are final race defense. Commit performs exactly one context.save; on error rollback and map stable code. Commit receipt contains batchID, commandID, counts, entry IDs and new revision, not raw rows. In-memory store does not prove persistent atomicity; disk store crash fault tests required.
commandID UUID plus requestDigest uniquely guards save/override/link commands: same ID+same digest returns receipt, same ID+different digest SOURCE_CONFLICT. BatchReceipt fileDigest unique globally. No await/yield between transactional revalidation and save; actor isolation alone does not imply Core Data queue safety. Cancel during save returns outcome by querying receipt; if process dies client asks commandStatus/batchStatus on resume. Unknown outcome remains checking, never display failure that encourages duplicate re-entry.
Preview/staging are transient, not canonical store writes. In-process review handles expire after 30 min/background interruption and delete staging; relaunch shows committed receipts, uncommitted preview must be reselected. Failed commit may retain protected review staging only while foreground handle valid; retry revalidates. Cleanup failure after durable commit yields success with CLEANUP_PENDING; startup removes orphan staging by random known paths, never follows source filenames/symlinks. Batch history contains no raw documents.
Restore/migration acquire maintenance lease, pause all writes, invalidate preview handles and increment storeEpoch after validated swap. Valid encrypted backup v1 exports allowlisted DTOs including identity key, namespaces, receipts and linked evidence; no raw documents. Checksums/counts, unique identities, refs, signs/currencies/refund caps/category IDs and timestamp bounds validate before candidate store creation. No archive merge. BackupArchive uses SYSTEM envelope/KDF unchanged; module ports provide data snapshot and candidate validation only. Restore failure leaves current store intact. Migration v1 initial model; future v2 requires version/hash, explicit mapping if non-lightweight, verified protected pre-migration backup, failure read-only recovery and tested prior binary/store rollback; never downgrade in place or open empty ledger on failure.

## UI contract and decisions
Use stable row tokens + safe row ordinal/code, editable drafts, suggested category/reason, explicit override and review counts. Commit enabled iff all included rows valid and duplicate/refund decisions resolved or explicitly retained unresolved, source conflicts excluded, preview current. UI states/errors in STATE-CONTRACT.json and INTERFACES.swift.txt are authoritative; UI role chooses visuals/accessibility under its separately approved profile. No UI Profile consumed because it does not exist yet. All module choices refine approved conservative policies; no CHANGE_REQUEST needed. Provider-format compatibility and device build/performance/security remain NOT_RUN. Fresh independent DESIGN review and MA-Q1–5 Owner grading are required, with no self-grading.

# Synthetic bill adapter profile v1
These are invented acceptance fixtures. They do not establish compatibility with real WeChat/Alipay exports. Production adapters require separately captured redacted format evidence, versioned profile specs and tests; no auto-detection guesses.

File: UTF-8 optionally one BOM; no GBK/UTF16 guessing. RFC4180 CSV with CRLF/LF, quoted commas/newlines and doubled quote escape; reject NUL, invalid UTF-8, duplicate headers, inconsistent fields, unterminated quotes. Never evaluate spreadsheet formulas, URLs or paths. A cell beginning =,+,-,@ is inert text; sign parsing applies only to typed amount grammar. Spreadsheet exports must prefix hazardous text with apostrophe; raw financial numeric cells use exact safe numeric serialization.
First record exactly `PADF-SYNTHETIC-BILL,1,WECHAT` or `PADF-SYNTHETIC-BILL,1,ALIPAY`. Second record exact ordered header:
`transaction_id,original_transaction_id,kind,status,amount,currency,occurred_at,merchant,location_text`
Exactly one marker maps profile `padf.synthetic.wechat.v1` or `padf.synthetic.alipay.v1`; mismatch requested provider, unknown version/headers/encoding -> UNSUPPORTED_EXPORT, show row ordinal and code only. No archives, spreadsheets, macros or attachments accepted. Do not unzip or traverse file names.

kind = spend|refund; status = settled|pending|cancelled. Only settled included; pending/cancelled rows yield NON_SETTLED_ROW and require explicit exclusion. amount grammar `[0-9]+(.[0-9]+)?` for spend or `-[0-9]+(.[0-9]+)?` for refund (literal dot); no leading plus, exponent, group separators or implicit unit conversion. Zero/overflow/excess currency decimals reject. amount integer string and ISO code canonicalize under registry v1. occurred_at strict RFC3339 with explicit offset and seconds; no locale dates or inferred zone. original_transaction_id only meaningful for refunds. Merchant required nonempty, max 1024 UTF8 bytes; location_text optional <=4096 UTF8 bytes; IDs <=256 UTF8 bytes. Blank transaction ID is supported only by candidate review algorithm. Original IDs HMAC derived same namespace/provider; raw IDs deleted with staging after review, only protected digests persist.

Limits: file <=10 MiB, <=10,000 data rows, row <=256 KiB including embedded newlines, <=9 cells, each generic cell <=16 KiB, quote nesting not applicable. Bound parser buffer before allocation; stop at first quota breach FILE_TOO_LARGE. File picker security-scope only for copy; reject directory/non-regular file/symlink, never construct paths from cell/file name, random protected staging path and cleanup allowlist. Fail changes during copy by copying once then hashing/parsing the immutable staged bytes. Validate complete file before review; invalid rows excluded explicitly, no silent truncation. Cancel probe <=100 rows.

Profile normalization version is part of SourceObservation and immutable source digest contract. Profile upgrades do not re-key existing identities or reinterpret old observations automatically; matching existing strong ID with changed economics requires conflict review. Unknown future profile unavailable, never fallback to synthetic profile.
