App → LedgerPresentation + the five named adapters. LedgerPresentation → LedgerApplication + DesignSystem. LedgerApplication → LedgerDomain. Aggregate edges expand one-for-five; no dependency is omitted.

Each adapter → LedgerApplication + LedgerDomain. No adapter-to-adapter or adapter-to-Presentation imports. Badges show full graph fan-in; the adapter aggregate is expanded in Adapters.

Node responsibilities

App. The sole composition root wires LedgerPresentation and the five concrete adapters: LedgerPersistence, BillImport, CategoryRules, LocationAccess and BackupArchive.

LedgerPresentation. Depends on LedgerApplication and DesignSystem. Cannot depend directly on persistence or other adapters.

Adapters ×5. Aggregate of exactly five packages. App depends on each; each depends on LedgerApplication ports and LedgerDomain. No adapter-to-adapter or adapter-to-Presentation dependencies.

DesignSystem. Presentation dependency only. Visual tokens/components require the separately approved UI Profile; this architecture viewer establishes no app UI design.

LedgerApplication. Depends only on LedgerDomain; coordinates adapters through ports. Actual graph fan-in is 6 (Presentation plus five adapters).

LedgerDomain. Money, ledger and provenance invariants; no UI, storage or permission framework. Actual graph fan-in is 6 (Application plus five adapters).
