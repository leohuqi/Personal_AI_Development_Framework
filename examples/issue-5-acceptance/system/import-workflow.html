Expense Ledger · Flowchart

Review first. Commit atomically.

Selected exports are validated and reviewed before explicit atomic commit; cancellation and failures preserve the canonical ledger.

Keep provider evidence beside edits. A provider/account/transaction ID is the strongest identity; deterministic fingerprints require review when ambiguous. User category overrides always win.

Unresolved refunds remain auditable and stay out of settled net totals until linked. Crash before commit leaves ledger unchanged; after commit, reopening batch ID returns the committed result.

Node responsibilities

Select exported file. User picks a previously exported WeChat/Alipay document. Copy to protected staging; maximum 10 MiB, 10,000 rows and 256 KiB per row. No provider login.

Detect and validate. Detect supported profile, normalize and validate with bounded streaming parser. Never guess an unknown financial format. Retain provider/profile/version, source-file hash and source row identity.

Preview and review. Local category rules provide versioned reasoned suggestions, user overrides win. Ambiguous duplicates require review. Retain unresolved refunds and exclude them from settled net totals until linked; preserve source evidence. Import never automatically requests GPS.

Confirm import?. Only an explicit user confirmation authorizes the ledger transaction. Cancellation discards staging and preserves ledger.

Commit one batch. Persistence commits all entries, source/refund/override records atomically. Strong provider/account/transaction identity or reviewed fingerprint handles duplicates across overlapping exports. Same file hash prevents repeated batch commit.

Saved + cleaned. Canonical ledger is durable; delete staging after completion. Crash after durable commit: reopening the batch ID returns the committed result. No partial commit.

Stop: unsupported input. Unknown profile, header, encoding or quota violation stops import. Actionable report uses row numbers/codes by default. Ledger unchanged; protected staging cleaned on review completion/cancellation.

Cancel + discard staging. Cancel before commit removes staging only. Raw source documents are transient and deleted after completion or cancellation; never used as portable backup.

Rollback / safe retry. Crash before durable commit, locked store, disk full or transaction failure cannot leave partial entries. Retry must remain idempotent. Persist safe error codes/counts only, no amounts, merchants, coordinates or raw provider IDs.
