The canonical ledger stays in the app sandbox. User-selected documents are untrusted input; backup is an explicit encrypted export. OS boundaries are expanded in Deployment.

Current GPS is a present observation with consent, time and accuracy. It is never inferred to be a historical purchase location.

One iPhone. One native process.

The iPhone app uses OS location, device authentication and protected storage, with encrypted manual export to the user-selected file provider.

Build baseline: Xcode 26.0 · Swift 6.2 · iOS 26 SDK. Runtime target: iOS 17+. One process; no server, remote packages or provider API. These are design decisions, not application build results.

Backup envelope v1 uses PBKDF2-HMAC-SHA256 (600,000 iterations), random salt and AES-256-GCM. Password is not stored. Restore validates a candidate store before replacing the current one.

Packages point inward

The composition root wires presentation and adapters; presentation calls application ports and the domain stays independent of UI, storage and permissions.

Each adapter → LedgerApplication + LedgerDomain. No adapter-to-adapter or adapter-to-Presentation imports. Badges show full graph fan-in; the adapter aggregate is expanded in Adapters.

Five adapters, two shared contracts

Every concrete adapter depends on application ports and domain policies, with no dependencies between adapters.

No cycles. No generic Common package. Domain remains independent of SwiftUI, Core Data and Core Location. Cross-adapter coordination belongs in Application.

Review first. Commit atomically.

Selected exports are validated and reviewed before explicit atomic commit; cancellation and failures preserve the canonical ledger.

Inspect a node by name

Keep provider evidence beside edits. A provider/account/transaction ID is the strongest identity; deterministic fingerprints require review when ambiguous. User category overrides always win.

Unresolved refunds remain auditable and stay out of settled net totals until linked. Crash before commit leaves ledger unchanged; after commit, reopening batch ID returns the committed result.
