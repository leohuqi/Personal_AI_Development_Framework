Expense Ledger · Deployment

One iPhone. One native process.

The iPhone app uses OS location, device authentication and protected storage, with encrypted manual export to the user-selected file provider.

Build baseline: Xcode 26.0 · Swift 6.2 · iOS 26 SDK. Runtime target: iOS 17+. One process; no server, remote packages or provider API. These are design decisions, not application build results.

Backup envelope v1 uses PBKDF2-HMAC-SHA256 (600,000 iterations), random salt and AES-256-GCM. Password is not stored. Restore validates a candidate store before replacing the current one.

Node responsibilities

Expense Ledger. Build baseline: Xcode 26.0, Swift 6.2 and iOS 26 SDK; minimum iOS 17. App + local Swift packages, no remote package dependencies. App composition wires Presentation plus LedgerPersistence, BillImport, CategoryRules, LocationAccess and BackupArchive. These are approved design versions, not an asserted build or installed Xcode version.

Protected local store. Canonical ledger plus protected staging/logs. Apply complete file protection, including WAL/SHM; defer store work while locked. No automatic OS cloud backup for the app store/staging under the manual backup policy.

Core Location. Only explicit current-location requests. Denial, timeout, reduced accuracy or no fix must preserve saving and import; keep unknown/existing evidence.

Device authentication. Single local OS user; device passcode and sandbox are the primary boundary. Optional sensitive-screen lock uses OS authentication and is not a separate encryption scheme.

OS file provider. Explicit manual encrypted backup only. Provider may sync externally at the user-selected destination. Passphrase not persisted; forgotten passphrase cannot be recovered. Restore validates a candidate store before swapping.
