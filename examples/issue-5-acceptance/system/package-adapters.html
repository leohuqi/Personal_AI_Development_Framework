Expense Ledger · Dependency graph

Five adapters, two shared contracts

Every concrete adapter depends on application ports and domain policies, with no dependencies between adapters.

Ten edges expand the five adapters’ dependencies. The core view shows App’s five composition dependencies as one explicit aggregate edge and Application → Domain.

No cycles. No generic Common package. Domain remains independent of SwiftUI, Core Data and Core Location. Cross-adapter coordination belongs in Application.

Node responsibilities

LedgerPersistence. Core Data adapter, model and migrations. Depends on LedgerApplication and LedgerDomain only; App creates and wires it.

BillImport. Provider export adapters and supported profile registry. Depends on LedgerApplication and LedgerDomain only; App creates and wires it.

CategoryRules. Deterministic local rules and user mappings. Depends on LedgerApplication and LedgerDomain only; App creates and wires it.

LocationAccess. Core Location foreground adapter. Depends on LedgerApplication and LedgerDomain only; App creates and wires it.

BackupArchive. Portable schema, authenticated encryption and file adapter. Depends on LedgerApplication and LedgerDomain only; App creates and wires it.

LedgerApplication. All five concrete adapters depend on application-defined ports. Application coordinates adapters without referencing concrete implementations. Badge is full graph fan-in, including Presentation.

LedgerDomain. All five adapters and Application depend on domain policies. No dependency from Domain to UI, storage or permission frameworks.
