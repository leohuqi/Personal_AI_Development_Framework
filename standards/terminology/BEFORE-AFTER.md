# 按语境判断用词

以下都是框架编写的合成案例，不代表任何项目的真实缺陷、用户研究或实测收益。机器回归输入见[案例数据](REGRESSION-CASES.json)；它不是自动替换表。

| 示例 | 处理方式 |
| --- | --- |
| “架构资料的可消费性需要核对” | 可写成“需要核对架构资料是否便于查阅和使用”，保留原检查范围。 |
| “Coder 请按规范消费路径查阅接口定义” | 可写成“Coder 请按阅读路径查阅接口定义”，保留原路径与前置条件。 |
| “本例用 C4 Container 展示所有代码类” | 存在概念错误。Container表达应用和数据存储，纠错不属于自动等义润色，应确认原意。 |
| “消息消费者按事件标识去重” | 保留。“消费者”在消息系统中含义准确。 |
| JavaScript闭包、ML输入分布漂移 | 在对应专业语境保留，必要时补解释。 |
| Agent、Workflow、Tool、Skill、Model | 分别解释职责；读Skill不代表工具已执行，也不授予权限。 |
| API路径、Schema字段、ID、SHA和状态枚举 | 保留标识；改名须按相应技术变更处理。 |

自动检查不能证明语义等价。核对原文的主体、条件、否定、范围、权限、数据归属、异常和恢复顺序；历史审批与执行记录保留原文。合成案例不能计入真实项目问题或改善统计。
