# PADF v0.3.8

本版清理框架的项目专属依赖，并将文档组织、Feature导航、引用式追溯和日常维护整合为通用方法。主变更：[PR #31](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/31)、[PR #32](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/32)；正式发布日期和目标提交以[GitHub Release](https://github.com/leohuqi/Personal_AI_Development_Framework/releases/tag/v0.3.8)为准。

## 主要变化

- 项目专属需求、目录、状态和批准留在项目自身。实际接入与试点评估移出当前框架，原始历史通过[独立历史入口](../history/project-pilots.md)追溯，不进入正式Skill默认阅读路径。
- [文档标准](../../standards/documentation/README.md)按阅读目的组织一个统一入口，先说明能回答的问题，再列短链接；一个权威正文，详细版本和审计按需展开。
- [project-documentation-curator](../../.agents/skills/project-documentation-curator/SKILL.md)为按需共享能力，Lite默认、Standard覆盖相关阶段、Full用于首次或获授权整体复核；不新增角色或固定前置步骤。
- [引用式RTM](../../contracts/requirements-traceability.md)复用原Catalog/需求/设计/实现/TC/Run，支持多对多与双向查证。未来功能显示缺口，局部技术PASS、完整AC和Owner验收保持区别。
- PA、SA/MA、Coder、QA、Master和Reviewer随交付维护当前受影响内容。来源修订、观察时间、生成时间分开；生成视图覆盖前检查过期，历史批准保持实际旧版本。

## 验证范围

[合成演练](../../tests/documentation/README.md)包含单文件小项目、多Feature导航和追溯、临时Git版本变更、派生过期及局部状态观测。独立Reader实际查阅来源并在新隔离副本完成一次局部文档维护，Reviewer检查准确diff、原始证据和修正。最终准确SHA的QA/Review/CI证据保存在两个PR的评论与[评审中心](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)。

这些结果验证框架方法与合成维护，不证明实际应用功能、真人阅读效率或所有文档工具已集成；本轮未创建前端门户，未执行浏览器/键盘或真人可用性验收。现有Engineering、Architecture、Terminology、Design Gate和G-01保持；未纳入其他待审PR。

## 接入与回退

项目固定采用的tag/commit，从当前切片增量更新所需Skill及引用规范。已有README、Markdown或文档工具均可复用，不要求Linear、固定目录、门户服务或独立文档数据库；不批量搬迁旧规范，不补造历史证据。示例测试适配器只用于框架演练，不作为项目运行依赖。

本版不声称已完成所有角色正文精简和协议合并。接入项目自主决定采用范围，不因发布自动升级。需要回退时恢复项目此前批准的PADF版本及匹配文件，保留项目既有文档、测试和审批历史；回退不授予生产或破坏性操作权限。
