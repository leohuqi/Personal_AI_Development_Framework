# PADF v0.4.0

本版在v0.3.9基础上明确项目文档中心和每次交付主动更新的要求。主变更：[PR #35](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/35)；正式日期和精确目标以[GitHub Release](https://github.com/leohuqi/Personal_AI_Development_Framework/releases/tag/v0.4.0)为准。

## 主要变化

- [文档标准](../../standards/documentation/README.md)要求项目建立唯一可读中心，README提供入口；小型任务可由README自身承担，多功能项目可复用静态HTML、现有文档工具或Markdown导航，不强制另建网站。
- 每次需求/设计交接、功能开发/修复及质量/决定变化时，原负责Agent主动检查文档影响、更新权威来源及准确引用、同步受影响中心、运行实际检查/生成并报告结果。无影响说明依据；Master收件核对，未同步或检查失败不能写已完成。
- 生成式中心在接入项目既有CI中覆盖相关PR与主分支更新，包含所有展示输入及生成器/模板/配置；先检查已提交结果/来源版本，再隔离生成比较，不能先覆盖旧页来掩盖过期。
- [共享Skill](../../.agents/skills/project-documentation-curator/SKILL.md)、Master、共用方法和交付/PR模板口径一致。接入时明确责任、来源、实际命令/触发与访问方式；日常默认Lite，不新增角色、维护阶段或逐次批准。

## 验证与边界

[独立QA](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/35#issuecomment-6515942485)真实使用隔离合成材料完成：单README维护；原Catalog新增未来功能、提交来源后更新派生入口；旧页过期/旧SHA不符被拒；缺工具/CI时保留旧输出并交付未同步缺口。结构96与既有文档9项检查通过。[独立Reviewer](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/35#issuecomment-6515953363)另核原始操作、最终入口及准确版本，APPROVE、无开放发现。

这些验证支持框架方法和合成维护，不代表真实接入项目CI、实际门户交互、业务或真人阅读效果已验证。没有创建通用门户引擎、常驻同步器或公开站点；相关项目工具/CI须实际配置，未配置诚实保留缺口。最终发布目标QA/Review/CI及原授权见[评审中心](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)和发布准备PR评论。

## 接入与回退

项目批准并固定采用v0.4.0或精确commit，在当前获授权接入/交付中核对既有中心和维护方式；已有中心接续，无中心安排有界补建，不能只升级版本就宣称接入完成。生成式项目落实实际命令/输入依赖/PR及主分支检查；静态Markdown无需新增构建或专用CI。历史文档不强制回填，缺口不自动阻断无关授权工作。

需求、设计、Catalog、TC/Run和批准仍各维护原权威来源；中心只组合导航/关系，不复制一套规格或重算验收。机器Schema、路由、Design Gate、G-01及Owner决定/编码/合并/部署权限保持；本版要求更新不授予未授权外部写入或公开部署权。

需要回退时恢复项目此前获批PADF版本（如v0.3.9）及匹配文件；保留项目现有文档中心、来源/决定与历史证据，任何工具或CI移除另按项目实际授权处理。发布本身不自动升级应用或修改其门户，也不撤销项目单独验收过的成果。
