# PADF v0.3.7

本版依据PKMS已有工程实践完善PADF的方法规范，让框架能指导项目建立适合自身的测试策略，并让Master在使用其他项目作为参考时保持当前任务边界。主要变更与讨论见[PR #30](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/30)。

## 主要变化

- [工程方法](../../standards/engineering/README.md)：明确SA、PA、Module Architect、Coder、QA、Reviewer和Master在测试策略、功能场景、TDD、调试、追溯与报告中的责任；按实际任务和风险裁剪。
- [追溯和报告](../../contracts/requirements-traceability.md)：复用项目既有用例、工具与结果，区分局部技术证据、完整AC验证和Owner验收；Functional类型可跨测试层级。
- [任务与上下文](../../governance/context-loading.md)：分清修改对象、允许动作和只读参考；案例项目的命令、历史批准和Handoff不自动转移授权。最新Owner澄清优先，接续已有Agent时仍核对当前任务。
- [Superpowers Lite](../../integrations/superpowers-lite.md)：固定来源并选择性采用TDD、系统调试和完成前核验，不新增规划、调度或重复审查流程。

## 证据与限制

[PKMS应用评估](../enhancements/engineering/README.md)基于已有项目记录：测试边界和追溯已有具体作用，产品TDD长期收益、开发效率和Owner阅读效率尚未充分证明。评估没有重跑PKMS测试或修改其项目，PR合并与业务验收仍是不同事实。

本版交付方法、角色和文档约定，没有新增PADF工程测试执行器、合成工程或专用CI。原Design Gate、G-01和Owner权限保持；旧项目无需补齐新的机器字段或重建历史测试。仓库原有验证结果只说明相应检查范围。

## 接入与回退

项目自主决定是否采用并固定版本；发布不会自动升级PKMS、PQA或其他项目。优先复用已有测试策略、AC/TC、工具和报告，只为当前变更补充必要证据；不按文件或测试数量判断质量。

需要回退时，恢复项目此前批准的PADF版本及其匹配的Skill、契约和工作流；保留既有项目测试结果和审批历史。回退不授予生产操作或破坏性变更权限。
