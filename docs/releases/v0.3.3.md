# PADF v0.3.3 版本变更

本版将角色成果优化与 G-01 Master 主动门禁一并发布。实现来自 [PR #13](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/13) 与 [PR #16](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/16)，沿用 V0.3 角色体系和 V0.2 通信协议；不新增常驻编排或授权服务。

## 角色与主成果

- 新增 Product Analyst：负责 High Level Specs、Feature Catalog 和产品意图；Module Designer 结合获批系统方案与适用已确认 UI，细化实施级 Feature Specs，Master 协调真实 Handoff/ACK。简单任务可有理由合并步骤，不能让 Coder 猜测产品行为。
- Solution Architect 提交可连贯阅读的完整系统方案，覆盖职责、接口、数据、正常及失败流程、质量目标和演进；在 Catalog 按 Very High/High/Medium/Low/Very Low 评估复杂度、依据、依赖与不确定性。Master 结合价值、功能关系和风险规划 milestone/iteration。
- UI 按概念图 → Figma 设计与精确版本确认 → 有边界原型授权及批准前端栈下的高保真运行原型收敛；Module 可先消费已确认 Figma，避免等待最终前端形成循环。
- QA 提供可追溯 Test Cases 与逐版本 Test Results，明确步骤、预期、实际、证据、缺陷和未测项。Context Coordinator 提供共享版本、决定与恢复交接能力，进度归 Master。
- Master 对问题推进、内容充分性、跨角色一致性、方案整合与交付质量负责；共用研究、消息和交接规则集中维护，主成果在前，审计作为附录。Owner 可在[统一评审入口](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)或对话反馈。

## G-01 主动操作保护

合并、启动编码、发布、生产部署、Owner 验收和标记 Done 六类操作，遵循 Owner Request → Master Preflight → Readiness → Authorized Action → Evidence Reconciliation。

- 只读评估器返回 READY/BLOCKED/NEEDS_OWNER_DECISION；Owner 操作请求不隐式豁免必需 CI/QA、真实独立 Review、准确版本、发现与关键依赖。
- 实际调用前重读来源、重新评估并核对语义摘要；合并须原子匹配 HEAD。当前风险与旧设计快照协调后重跑 Design Gate，不能用低风险旧快照降级。
- 分别记录实现、CI、QA、Review、合并、验收、Done 与部署；PR 源 HEAD 和实际 merge SHA 分开保存，合并不能自动代表验收或 Done。
- 原有有效授权范围内的真实分派继续，无需逐次新批准；重大决定、业务编码、合并、发布、生产与破坏性操作仍各自授权。

## 接入、限制与回退

接入项目须明确批准并固定 v0.3.3 或精确 SHA，同步所需 Skill、契约、治理、工作流、评估器和测试。两阶段规格与 staged UI 是兼容扩展：旧格式不得冒称完成新流程；本次发布不自动升级 PQA/PKMS 或授权业务编码、部署。

评估器只检查调用方已核验的快照，不认证远端 Owner/Agent 身份，不执行操作，也不提供 GitHub 服务器拦截或后台监听。Linear Merge→Done 具体配置仍未验证或修改，继续采用事前事后核对与有授权补偿。合成测试不代表真实 Figma 制作、用户研究、应用或生产测试。

发布失败时保留未发布状态，先补门禁；发布后保留不可变标签，不移动历史版本。需要退回的接入方可固定 v0.3.2@`15866db0cf09c5ac5d44b5bdb5c62e311c553ee2`；后续修复通过新版本交付，不以本发布授权执行 main 回滚或生产操作。
