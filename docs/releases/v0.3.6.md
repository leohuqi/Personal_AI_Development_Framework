# PADF v0.3.6

本版把已在PKMS试点验证的架构设计与术语治理方法沉淀为通用框架能力，并让同一职责的Agent优先接续原任务。实现来源为[PR #24](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/24)和[PR #25](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/25)；Owner验收、合并及发布决定保留在[统一评审入口](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)。

## 主要变化

- **按需选择架构深度。** Master依据当前范围、复杂度与风险选择Lite、Standard或Full；scope与深度分别表达，简单改动可复用基线，复杂系统按C4、轻量arc42和ADR形成可连续阅读的方案。Solution Architect与Module Architect沿现有角色深化系统和模块，不新增角色或阶段。
- **分层设计与真实架构图。** 提供系统、容器、组件、运行、数据和部署样例；8张图保留源模型、HTML、SVG和PNG。图表已完成真实浏览器渲染、逐图实看及独立复渲染，Standard父容器标注修复后再次核对。
- **通用术语治理。** 新增六领域单源词表、Markdown生成、共享Terminology Governance Skill及受保护内容检查。词条区分通用与项目专属、正式来源与项目建议；通用词条发布时仍为`PROPOSED`，不会因框架发布自动变成项目批准术语。
- **优先接续已有Agent。** 同一项目、职责和有效授权范围的增量、返工优先继续已有真实会话；不可接续、上下文不足或独立性不满足时再新建，并从准确成果恢复。旧执行回执不能证明本次完成，旧SHA批准不能覆盖新SHA。
- **兼容原门禁。** Profile是只读建议，不能提供缺失角色、批准、图表、UI输入或Review；术语辅助器不自动改写；原消息schema、Design Gate、G-01、UI Mockup/Impeccable和Owner授权边界保持。

## 接入与迁移

接入项目按批准版本整体同步相关Skill、契约、工作流、标准、样例和检查器，并在项目自己的AGENTS.md保留领域专属规则。框架发布不自动升级PKMS、PQA或其他项目，也不把PKMS术语接受升级为PADF通用术语批准。

现有项目可先使用架构深度选择和按问题阅读，不必把既有有效设计重写为Full。术语治理按需启用：先读取项目已有词表和批准文档，只提示与当前决策相关的候选；技术标识符、协议字段、API路径、状态枚举和历史证据不做批量替换。

Agent接续不要求新增台账或常驻服务。继续使用原任务/共享上下文保存实际会话、准确成果和未决项；每次接续仍核对当前授权、Task Contract、HEAD、规格、依赖及真实工具回执。Designer、Coder或Master不能通过改名成为独立Reviewer。

## 验证与限制

PR #24的两项CI和独立Review通过。PR #25在PR #24合并后，以新main为准确Base重新完成两项CI、针对性QA及独立Review，结论APPROVE，无开放P0–P3；原Standard组件图父容器P2已修复。Profile 25组、术语16组和图源12组负例通过；8图的真实渲染、实看和独立复渲染证据保存在仓库中。

这些结果验证框架规则、合成场景、文档和图表产物，不证明真实接入项目的运行、数据库/存储、安全性能、恢复、客户理解或跨项目收益。术语资料阅读不等于用户研究，辅助检查不认证语义等价、现实身份或批准。发布准备提交的准确CI、独立复审和最终tag/Release回执继续记录在发布PR与统一评审入口。

## 回退

旧tag保持不可变。接入方需要撤销升级时，恢复此前获批准的固定PADF版本及匹配的Skill、契约和输入；不要把v0.3.6的新Profile、术语或接续规则与不匹配的旧检查器混用。回退不授予生产或破坏性操作权限，后续修复通过新版本发布。
