# PADF v0.3.1 版本变更

本补丁修复设计门禁的职责路由、风险审查和 UI Profile 批准漏洞，保留 V0.3 的角色分工与独立编码授权。正式发布与合并须在新 SHA 独立审查和 Owner 批准后进行；本文件不代表发布已完成。

## 修复范围

- 缺少必需 UI 阶段时，返回 BLOCKED / MISSING_UI_DESIGN_STAGE，不能因 UI 阶段不存在而跳过校验。
- 已知模块影响只能选择 module/both；system 不能替代 Module Architect，系统与模块影响同时存在时须选 both。
- 强制 DESIGN 审查根据 impacts 与 risk_flags 中已知强制风险类别共同判定；S/M 共享组件或设计系统变更不能因风险标签漏填而跳过。
- 需要 UI 时，Profile 必须有批准状态、批准证据及精确版本绑定；草稿、版本固定、原型、CI 或编码授权本身不能替代 Profile 批准。

## 输入迁移

schema 标识保持不变。UI 任务根层须补充：

```yaml
ui_profile_ref: docs/design/ui-profile.md@<exact-approved-commit>
ui_profile_status: APPROVED
ui_profile_approved_ref: docs/design/ui-profile.md@<exact-approved-commit>
ui_profile_approval_ref: "<verified-owner-decision-permalink>"
```

UI 阶段的 profile_ref 也须指向相同版本。旧输入缺少批准信息时现在会 BLOCKED，这是预期的安全修正，不能以默认 APPROVED 迁移。Owner 可以明确批准任务范围内的替代基线；采用相同字段和版本约束。Master/Reviewer 仍须核验真实批准人的权限、范围与版本，纯元数据评估器不会访问远程证据。

## 接入与发布边界

- v0.3.0 标签不移动；补丁使用新的 v0.3.1 标签。
- 接入项目固定新的已批准 tag/SHA，并同步契约、实现和测试，不只替换单个函数。
- 本补丁不修改 PQA，不批准其 UI Profile、CR-001、合并或生产操作。
- 验证包括设计门禁回归、CACF 协议、编排/质量元数据、结构检查及试点依赖检查；这些不代表实际 Agent、图表工具或生产环境验证。
