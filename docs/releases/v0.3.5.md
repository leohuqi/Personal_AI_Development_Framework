# PADF v0.3.5

本版让小团队协作、UI制作及文档评审更直接，保留必要授权与真实证据门禁。实现来源为[PR #22](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/22)，Owner已[批准合并和发布](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/22#issuecomment-6379499398)。

## 主要变化

- **小团队协作与不过度设计。** 明确Owner/PM、技术成员与Agent职责；任务与交接先给最小可用内容，九个角色按当前验收和真实风险停止细化。文档、评审、PR与日常沟通同样结论/请求先行，同一内容维护一份，用链接复用，只补变化。详见[共用规则](../../workflow/role-work-method.md#文档评审与沟通同样最小充分)和[团队职责](../../workflow/small-team-collaboration.md)。
- **概念直接进入前端Mockup。** 取消强制Figma；概念图经Owner或获授权成员确认后，按批准前端栈与原型授权制作高保真交互Mockup，用[Impeccable](../../integrations/impeccable.md)检查体验和一致性。工具建议服从已批准Profile与组件，不静默安装/升级工具。
- **当前UI风险不可被可选标记隐藏。** 所有角色/阶段上的当前Impeccable报告都检查来源、目标、Profile、Skill、结论与发现；未修复P0/P1及未获逐项条件处置的P2阻断。明确另一固定未选草稿保留可选语义。

## 接入与迁移

按批准版本一并同步Skill、契约、工作流、集成说明、门禁与测试；只复制单个Skill会丢失共用规则。框架发布不自动升级PQA、PKMS或其他接入项目。

UI推荐 `ui_delivery_mode: concept-mockup`；`staged`别名及省略模式同样执行新规则。L1为概念草稿，L2为已确认概念，L3为实际前端交互Mockup。旧Figma字段不自动变成概念确认或合格L3；迁移按[UI契约](../../contracts/ui-design.md)补准确概念、有效确认、前端栈/原型授权、实际交互和当前Impeccable报告。已有有效来源可复用，缺证据保持阻断。Module可先消费确认概念与SA方案细化规格，避免等待最终Mockup产生循环。

普通概念可由获授权成员确认；重大设计/Profile/风险接受仍归Owner。概念确认、原型授权、业务编码、合并、发布和生产分别核对，简化文档不省略必要事实或真实执行。

## 验证与限制

实现及文档分别有准确SHA的[独立审查](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/22#issuecomment-6379419388)，当前无开放发现；UI-R1修复及独立探针见[前序报告](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/22#issuecomment-6379285922)。399项专项回归验证概念确认、Mockup、Impeccable绑定及正负边界；其余Design/CACF/G01回归通过，证据在原报告，不重复粘贴日志。最终发布目标的文档审查与CI另在[评审入口](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)核验，不将旧SHA结果改写成新实测。

评估器仍为只读元数据检查，不认证现实身份、引用内容或批准，不提供服务器拦截/后台监听。合成测试不证明真实应用UI、浏览器、Impeccable调用、联测或生产；未执行单独Owner验收/Issue Done，未改Linear自动状态配置。

## 回退

标签保持不可变，不移动旧tag。接入方需要撤销升级时，可恢复此前获批准的固定版本和匹配契约/输入；v0.3.4仍采用旧UI规则，不能与本版字段混用。回退不是生产回滚授权，生产操作仍须单独批准；后续修复通过新版本交付。
