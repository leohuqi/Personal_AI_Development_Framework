# PADF v0.3.4 版本变更

本版修复设计门禁对已有审查、多阶段产物及正式执行证据的漏检，来源为 [Issue #18](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/18) 和 [PR #19](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/19)。Owner 已验收该修复并明确批准合并及发布 v0.3.4；[批准原话](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14#issuecomment-6355557839)适用的实现源为 `a96eb001f225ab3a9568d74e2168ece31e3d85cf`，合并提交 `58c0d38d873b5778d658f2a1c7b5ff68c918394d` 的文件树与之相同。版本文档及最终发布目标的准确检查、独立审查和 RELEASE 预检另见[统一入口](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)，不把原实现审查自动延伸为新 SHA 批准。

## 修复内容

- **已有审查结果对所有规模生效。** 只要提交 DESIGN Review，就校验其独立性、结论、发现和精确产物覆盖；REQUEST_CHANGES、未修复 P0/P1、未按条件接受的 P2 均阻断。低风险跳过只适用于未提供审查的任务，不能覆盖已有拒绝或发现。
- **全部架构阶段逐一校验。** 检查所有必需 SA/Module 及图工具版本；both 按唯一、精确获批系统基线确定来源。数据库 schema/图与工作流图从全部必需架构产物集合核验，不依赖清单第一项，也不强迫无关模块复制 SQL。
- **正式执行链绑定当前任务和输入。** 当前 context、仓库、Task Contract、各阶段唯一 Dispatch/Execution、全部必需产物@SHA 相互匹配；Module Dispatch 的系统基线、状态、批准引用与 UI Dispatch 的 Profile 须匹配当前 Gate 和阶段。
- **实际依赖不能倒置。** both 的唯一系统来源须真实先行并被 Module Dispatch 直接依赖；完整 required stage 图中的所有专业祖先须真实先行、在 Dispatch 图中直接或传递可达。遍历穿过 Master/Context Coordinator 协调节点，但不为其伪造专业执行。合法的元数据清单重排、一般传递依赖和 module-only 复用已批准外部基线保留。
- **UI 证据与声明等级一致。** legacy/staged 均要求合法 L1/L2/L3；legacy L2/L3 也需可编辑高保真源，L3 另需交互证据。staged 的 Figma、精确确认、前端栈和原型授权约束保持。
- **G-01 跨入口继承阻断。** START_CODING 重新消费修正后的 Gate，外层 findings 为空不能掩盖内层缺陷；缺失或 null 正式编排链返回不足证据并阻断。

## 接入与补证

新增严格绑定仅适用于 `orchestration_validation_required: true`：
1. Gate 和链顶层补齐并匹配 `context_id`、`repository`、`task_contract_ref`；各 Dispatch 同属当前仓库。
2. 每个必需 PA/SA/Module/UI 阶段以 `orchestration_binding` 定位唯一 Dispatch/Execution，Handoff 覆盖全部必需精确产物引用；Module 的基线/批准和 UI Profile 使用当前准确输入。
3. 按实际先行来源核对阶段与 Dispatch 的依赖，不把下游之后补做的前序任务追认为先行输入。

legacy L2/L3 须补固定版本可编辑高保真源；若交互源同时充当高保真源，声明 `fidelity: high` 及 `editable_source: true`，并保留交互测试证据。已声明 staged 的任务继续满足原三阶段约束。旧输入缺证据时应 BLOCKED/补证，不以旧版本曾通过为迁移豁免。详见 [Design Gate](../../contracts/design-gate.md)、[Dispatch](../../contracts/agent-dispatch.md)、[UI 设计](../../contracts/ui-design.md)和[验证说明](../../tests/v0.3/README.md)。

未开启正式编排验证的路径不新增绑定要求；修复不授予编码、重大决定、合并、发布或生产权限。接入项目须明确批准并固定 v0.3.4 或精确 SHA，同步相关契约、评估器、工作流和测试；本发布不自动升级 PQA/PKMS。

## 限制与回退

评估器仍为纯只读元数据检查，不认证远端 Owner/Agent 身份、链接内容或真实批准，不启动分派/业务操作，不提供服务器强制拦截、后台监听或新授权服务。合成测试不代表真实 Figma、浏览器、业务数据库或生产运行验证；Linear Merge→Done 配置仍未验证或修改。

发布标签保持不可变；修复或撤销通过新版本/明确授权处理，不移动旧 tag，也不凭发布授权回滚 main 或生产。接入方如需撤销升级，可固定此前已批准的 v0.3.3@8a1fa8142c2a7304f8c5f2978fa557437a8942f6，但该版本仍存在本版修复的已知门禁缺陷，不能视为等效保护。
