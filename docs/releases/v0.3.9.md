# PADF v0.3.9

本版将主动需求发现、渐进澄清和版本化产品基线整合进现有 PA 方法，帮助把模糊业务目标转为可供设计使用的产品定义。主变更：[PR #33](https://github.com/leohuqi/Personal_AI_Development_Framework/pull/33)；正式发布日期和精确目标以 [GitHub Release](https://github.com/leohuqi/Personal_AI_Development_Framework/releases/tag/v0.3.9) 为准。

## 主要变化

- [PA Skill](../../.agents/skills/product-analyst/SKILL.md)主动发现业务缺口，每轮只处理少量高影响问题，给出推荐和业务影响，复用已经确认的信息。
- [产品定义](../../contracts/product-definition.md#需求发现与定义requirements-discovery--definition-v01)关联目标、能力、流程/用例、Feature与可观察AC；按规模裁剪，近期细化、远期渐进，不强制新建BRD或重复PRD。
- 来源类别与决定状态分别记录；确认须关联真实来源、权限及适用版本。研究、Agent推断/建议、沉默或测试通过不能替代Owner的重要业务决定。
- Master接收准确Feature基线、规则/AC、依赖及未决影响，协调下游；PA保持高层产品责任，Module结合SA/适用UI细化实施级规格。需求确认不等于Design Gate、编码授权或Owner验收。
- 最小Finding沿用 `Feature ID + Finding + Source + Impact + Proposed Action`，Master接收、PA分析；不新增跨阶段变更平台或自动任务分解器。跨轮汇总保留原ID/含义，变化显式关联前后版本/决定，交接前核对引用。

## 验证与限制

[能力评估](../upgrades/requirements-discovery-v0.1.md)汇总原有能力、缺口、文件影响和未验证项。[首轮实际证据](../../tests/requirements-discovery/RESULTS.md)保留十类合成输入/Agent回答及正确性检查；十项核心行为断言通过，另发现跨轮AC/规则编号与功能范围追溯问题。原失败保持原文，窄修正后[S03三轮重测](../../tests/requirements-discovery/RESULTS-R2.md)六项检查通过。

其余九例未在新方法上重跑；同一QA知道旧失败，无法分离学习与方法修正的作用。独立Reviewer实际审读原始回答、失败、修正和新回答后，对精确源作有界APPROVE；最终发布目标的QA/独立Review/现有CI见发布准备PR及[评审中心](https://github.com/leohuqi/Personal_AI_Development_Framework/issues/14)。这些结果不证明真实项目改善、长期一致性或普遍有效；大项目滚动计划与持续UI/架构需求修订尚未实测。

## 接入与回退

项目批准并固定采用tag/commit，按本次切片更新PA方法及相关规格/上下文引用；复用原文档和等价字段，无需重建需求库或回填全部历史。源和决定分别映射，不改代码标识符、现有机器Schema、路由或治理实现。未确认重要规则不并入正式基线，已确认内容仍须核验当前适用版本。

现有Design Gate、G-01和Owner权限继续适用；无新增角色、审批阶段、运行时或专用CI。框架发布不自动升级任何应用项目。需要回退时恢复此前获批PADF版本（如v0.3.8）及匹配文件，保留项目实际决定、需求和历史证据；回退不自动撤销业务决定，也不授予生产或破坏性操作权限。
