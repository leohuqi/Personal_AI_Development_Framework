# S05 实际 PA 回答 v1

输入 s05-u1（合成 Owner）；G-S05 是让设备借出和归还可控。当前已明确范围：登记成员申请设备与归还时间→管理员批准后发放→归还登记；USER_STATED / 场景内 CONFIRMED，适用此流程范围。分析出的缺口为 AGENT_INFERENCE / NEEDS_CLARIFICATION，不作为新增已批准功能。

| Feature / 关系 | 必须澄清的风险 | 候选业务 AC |
| --- | --- | --- |
| F-S05-01 提交借用申请 / 申请能力 | 设备已借出或同时申请时如何占用；归还时间是否必须在借出之后 | AC01：登记成员提交设备与有效归还时间，能看到申请已提交、尚未发放；缺必填资料不能误显示已借出 |
| F-S05-02 管理员审批与发放 / 依赖 F01 | 拒绝/撤回、批准后设备损坏或已发放他人、申请人与审批人同一人的处理 | AC02：审批未通过不发放；AC03：管理员拒绝后可看到明确结果，不形成借出记录 |
| F-S05-03 归还登记 / 依赖实际发放 | 谁确认归还；逾期、损坏或部分附件未还时能否记作已归还 | AC04：实际归还经有权人员登记后，借用状态可见；逾期/损坏如何处理待确认，不能直接写为自动罚款 |

本轮先问三项高影响问题：
1. 同一设备有多个申请时，推荐审批时再核对可用性、只允许一个实际借出；另一方案是提交即预占，能保护先申请者但会导致等待期间闲置。选哪种？
2. 归还由谁确认：推荐管理员核实设备及附件后登记，还是允许成员自报即归还？后者省工作但记录可信度降低。
3. 逾期或损坏本期如何处理：推荐标记异常交管理员人工处理，还是必须实现收费/赔偿规则？推荐前者以控制范围，收费规则如采纳需 Owner 明确。

之后再补申请撤回和自批边界，不一次穷举问题。F01～F03 优先级建议高，但冲突、归还权限、异常结果会影响当前验收，整体 NEEDS_REFINEMENT。上述 AC 的新规则仍为候选；不增加通知、支付、库存采购或运营后台。Master 负责澄清收件与后续 SA/UI/Module 协调；API、表结构、状态实现不由 PA 预定，无编码授权。
