# S01 实际 PA 回答 v1

合成独立场景；输入 s01-u1。目标 G-S01：减少活动室时间冲突，让居民知道预约是否有效。当前只有问题与“简单”的偏好明确，范围尚未确认。

建议先做 F-S01-01「查空闲并申请一个时段」与 F-S01-02「查看结果和取消自己的预约」的小切片；避免先加支付、积分或多场馆管理。两项均为 AGENT_RECOMMENDATION / CANDIDATE，理由是形成最短预约闭环；不是已批准功能。

本轮先确认三件会改变范围的事：
1. 谁可以预约：仅本社区成员，还是任何人？推荐仅成员，能明确使用资格；开放预约需要处理外部占用。
2. 谁决定预约成功：空闲即成功，还是管理员确认？推荐空闲即成功以减少管理负担；若有资格/用途审查则选管理员确认。
3. 冲突以什么为准：一个活动室同一时段只能一组，还是允许分区同时使用？推荐先按整个活动室独占；这直接决定冲突和可用时间规则。

待答后再确定可预约日期、时长及取消约束。候选业务 AC-S01-01：已具备预约资格且所选时段可用时提交预约，能看到明确结果；若该时段已占用，不能显示预约成功并能重新选择。资格、成功方式和冲突规则未决，此 AC 也为候选，不能交作有效基线。F-S01-01/02 均 NEEDS_REFINEMENT；可继续整理现有微信群中的典型冲突，暂停依赖上述答案的产品定义。技术接口和表结构留给后续设计。
