# 文档与追溯的有界演练

这是框架方法验证，不是文档平台、接入项目测试或门户部署。全部资料为合成；项目自行选择工具和格式，不要求复制本目录。

- **Case A**：[小项目README](fixtures/small/README.md)。一个文件承载目标、Feature/AC和未测状态；Lite只改当前引用，无新服务或批准。
- **Case B**：[多功能入口](fixtures/multi/INDEX.md)。导航来自原Catalog，完整正文在规格、QA和决定文件中；引用图演示多对多/反向查询、未来功能缺口与历史批准。
- **Case C**：`python3 tests/documentation/run-validation.py`在临时Git仓库修改/提交来源，检查旧SHA与新正文不符、提交后新SHA正确、历史批准不移动、来源/模板变化使已提交派生页失败、局部状态刷新与读取失败的时间限制。另由独立Agent在隔离副本处理一次合成代码变化的文档维护，实际结果链接见本轮PR。
- **Case D**：未参与构建的Agent从入口实际查找目标、Feature、需求设计、AC/TC/Run、当前决定和历史批准，记录真实路径、遗漏与限制；实际报告链接见本轮PR。阅读独立性不等于盲测或真人可用性实验。

测试适配器仅为这组夹具生成Markdown并验证引用，不是生产工具或新机器契约。测试不读取外部业务系统，不计算完整AC验收；临时Git用于精确来源验证，记录的合成Run不等于实际产品测试。文本/机械核验、独立Agent阅读、DOM、浏览器和真人可用性分别报告；本轮未创建UI，因此无DOM/浏览器/键盘或真人体验通过结论。

兼容性：可在无外部依赖、不同应用技术栈的仓库使用同一通用方法；本演练不证明所有文档工具已集成。原有Engineering/Architecture/Terminology、Design Gate与G-01保留，实际采用由项目固定版本并增量接入。
